# 痛经缓解功能使用说明

## 新增功能概述

本次更新添加了两个主要新功能：

### 1. 可配置的痛经发生概率

用户可以在配置文件中自定义痛经发生的概率分布，实现个性化的痛经模拟。

### 2. LLM智能判定消息缓解痛经

使用大语言模型(LLM)智能判断用户发送的消息是否对痛经有缓解作用，如果有缓解作用，则临时降低痛经等级。

---

## 功能1：可配置痛经概率

### 配置项说明

在 `config.toml` 文件中添加以下配置：

```toml
[dysmenorrhea]
# 无痛经的概率（0.0-1.0）
prob_none = 0.25

# 轻度痛经的概率（等级1-2，0.0-1.0）
prob_mild = 0.30

# 中度痛经的概率（等级3-4，0.0-1.0）
prob_moderate = 0.25

# 重度痛经的概率（等级5-6，0.0-1.0）
prob_severe = 0.20
```

### 使用说明

1. **概率总和**: 四个概率值加起来应该等于 1.0（100%）
   - 示例：0.25 + 0.30 + 0.25 + 0.20 = 1.0 ✓

2. **概率范围**: 每个值必须在 0.0 到 1.0 之间
   - 0.0 = 0% 概率
   - 1.0 = 100% 概率

3. **调整建议**:
   - **增加无痛经概率**: 提高 `prob_none` 到 0.4-0.5
   - **减少重度痛经**: 降低 `prob_severe` 到 0.05-0.10
   - **更多中度痛经**: 提高 `prob_moderate` 到 0.35-0.40

### 配置示例

#### 轻松模式（较少痛经）
```toml
[dysmenorrhea]
prob_none = 0.50      # 50%无痛经
prob_mild = 0.30      # 30%轻度
prob_moderate = 0.15  # 15%中度
prob_severe = 0.05    # 5%重度
```

#### 真实模式（符合医学统计）
```toml
[dysmenorrhea]
prob_none = 0.25      # 25%无痛经
prob_mild = 0.30      # 30%轻度
prob_moderate = 0.25  # 25%中度
prob_severe = 0.20    # 20%重度
```

#### 困难模式（较多痛经）
```toml
[dysmenorrhea]
prob_none = 0.10      # 10%无痛经
prob_mild = 0.20      # 20%轻度
prob_moderate = 0.40  # 40%中度
prob_severe = 0.30    # 30%重度
```

## 功能2：LLM智能缓解判定

### 功能说明

当用户发送消息时，插件会使用LLM智能判断消息是否对痛经有缓解作用。如果判定为有缓解作用，则临时降低痛经等级。

### 缓解作用消息示例

以下类型的消息可能被判定为有缓解作用：

- ✅ **关心安慰**: "你还好吗？"、"辛苦了"、"要好好休息哦"
- ✅ **实用建议**: "要不要热敷一下？"、"多喝热水"、"注意保暖"
- ✅ **情感支持**: "我理解你的感受"、"有我陪着你"、"我会照顾你的"
- ✅ **询问需求**: "需要我帮你做什么吗？"、"想吃点什么？"
- ✅ **分散注意力**: 有趣的笑话、温馨的故事、轻松的话题

### 不被判定为缓解的消息

- ❌ **普通闲聊**: "今天天气不错"、"你在干嘛"
- ❌ **无关话题**: 工作讨论、技术问题
- ❌ **负面言论**: 责备、不理解、冷漠

### 配置项说明

```toml
[dysmenorrhea]
# 是否启用LLM判定消息缓解痛经功能
enable_llm_relief = true

# 缓解效果持续时间（分钟）
relief_duration_minutes = 60

# 缓解时降低的痛经等级（0-6）
relief_reduction = 1
```

### 配置参数详解

1. **enable_llm_relief** (布尔值)
   - `true`: 启用LLM缓解判定功能
   - `false`: 关闭该功能
   - 默认值: `true`

2. **relief_duration_minutes** (整数)
   - 缓解效果持续的时间（分钟）
   - 建议范围: 30-120分钟
   - 默认值: `60` (1小时)

3. **relief_reduction** (整数)
   - 缓解时降低的痛经等级
   - 范围: 0-6
   - 默认值: `1` (降低1级)
   - 示例: 痛经等级从5降到4

### 使用场景示例

#### 场景1：轻度缓解
```toml
relief_duration_minutes = 30
relief_reduction = 1
```
用户发送关心消息后，痛经等级降低1级，持续30分钟。

#### 场景2：强力缓解
```toml
relief_duration_minutes = 120
relief_reduction = 2
```
用户发送非常贴心的消息后，痛经等级降低2级，持续2小时。

#### 场景3：短暂缓解
```toml
relief_duration_minutes = 15
relief_reduction = 1
```
适合频繁互动的场景，每次缓解持续15分钟。

## 工作原理

### 痛经等级计算流程

```
1. 生成基础痛经等级（基于配置的概率）
   ↓
2. 应用时间规律（第1天次一级，第2天峰值，之后逐天下降）
   ↓
3. 应用天数约束（等级 ≤ 剩余天数）
   ↓
4. 检查是否有LLM缓解效果
   ↓
5. 如果有缓解效果且未过期，降低相应等级
   ↓
6. 返回最终痛经等级
```

### LLM判定流程

```
用户发送消息
   ↓
检查是否在月经期 → 否 → 跳过判定
   ↓ 是
检查是否有痛经 → 否 → 跳过判定
   ↓ 是
使用LLM判定消息内容
   ↓
判定为有缓解作用 → 是 → 应用缓解效果
   ↓ 否
继续正常处理
```

## 注意事项

### 1. LLM API配置

此功能需要正确配置LLM API才能工作。请确保：
- MoFox-Bot的LLM服务已正确配置
- 插件可以访问LLM客户端
- LLM API有足够的配额

### 2. 事件类型兼容性

**重要**: MessageReliefHandler需要订阅用户消息事件。如果插件无法正常工作，请检查：

1. 查看MoFox-Bot的事件类型定义
2. 修改 `components/event_handlers.py` 中的 `init_subscribe`
3. 可能的事件类型：
   - `EventType.ON_USER_MESSAGE`
   - `EventType.ON_MESSAGE_RECEIVED`
   - `EventType.ON_PRIVATE_MESSAGE`

### 3. 性能考虑

每条用户消息都会调用LLM进行判定，可能产生：
- API调用费用
- 响应延迟

建议：
- 仅在私聊中启用此功能
- 设置合理的缓解持续时间，避免频繁触发
- 监控API使用量

### 4. 隐私保护

用户消息会被发送到LLM进行分析，请注意：
- 确保用户知情并同意
- 使用可信赖的LLM服务
- 不记录敏感消息内容

## 故障排除

### 问题1：LLM缓解功能不生效

**可能原因**：
- LLM API未配置
- 事件类型不匹配
- 功能被禁用

**解决方案**：
1. 检查 `enable_llm_relief = true`
2. 查看日志确认事件订阅是否成功
3. 确认当前处于月经期且有痛经

### 问题2：缓解效果不明显

**可能原因**：
- `relief_reduction` 设置太小
- 消息未被LLM判定为有缓解作用

**解决方案**：
1. 增加 `relief_reduction` 的值
2. 查看日志确认LLM判定结果
3. 调整消息内容，使其更具关怀性

### 问题3：概率配置不生效

**可能原因**：
- 配置文件格式错误
- 旧周期数据仍在使用

**解决方案**：
1. 使用 `/regenerate_cycle` 命令重新生成周期
2. 检查配置文件语法
3. 重启插件
