# 痛经系统重构说明

## 变更内容

### 1. 生理影响提示词优化
- **去除腹痛描述**：避免与痛经提示词语义重复
- 重点描述：疲劳感、身体沉重感、四肢酸软等非腹痛症状

### 2. 痛经等级调整
- **旧系统**：11个等级（0-10）
- **新系统**：7个等级（0-6）

### 3. 痛经逻辑重新设计

#### 原始逻辑的问题
- 痛经等级完全随机，每天都可能是任意等级
- 没有考虑痛经的自然变化规律
- 可能出现"等级6但只持续1天"的不合理情况

#### 新逻辑设计

```
痛经发展规律（以峰值等级5为例）：
月经第1天: 等级4 (峰值-1，渐入期)
月经第2天: 等级5 (峰值，最痛的一天)  
月经第3天: 等级4 (峰值-1，开始缓解)
月经第4天: 等级3 (峰值-2)
月经第5天: 等级2 (峰值-3)
月经第6天: 等级1 (峰值-4)
月经第7天: 等级0 (无痛经)
```

#### 核心规则

1. **每个周期独立随机**
   - 每个月经周期开始时随机生成痛经峰值等级
   - 第一周期和第二周期的痛经等级互相独立

2. **概率分布**
   - 25% 无痛经 (等级0)
   - 30% 轻度痛经 (等级1-2)
   - 25% 中度痛经 (等级3-4)
   - 20% 重度痛经 (等级5-6)

3. **时间规律**
   - **第1天**：峰值-1（渐入期）
   - **第2天**：峰值（最痛）
   - **第3天起**：每天下降1级，直到0

4. **关键约束**
   - **等级必须 ≤ 天数**
   - 这确保不会出现"等级6但只剩1天月经"的情况
   - 例如：如果月经只有3天，最高等级不会超过3

## 新痛经等级说明（0-6）

| 等级 | 描述 | 最少需要天数 |
|------|------|-------------|
| 0 | 无痛经 | - |
| 1 | 轻微隐痛 | 2天 |
| 2 | 轻度疼痛 | 3天 |
| 3 | 较明显疼痛 | 4天 |
| 4 | 持续疼痛 | 5天 |
| 5 | 明显疼痛 | 6天 |
| 6 | 强烈疼痛 | 7天 |

## 实际案例

### 案例1：重度痛经（峰值6）
```
假设月经期为7天，随机到痛经等级6：
第1天: 等级5 (峰值-1)
第2天: 等级6 (峰值，最严重)
第3天: 等级5
第4天: 等级4
第5天: 等级3
第6天: 等级2
第7天: 等级1
```

### 案例2：月经期较短（4天）
```
假设月经期只有4天，随机到痛经等级5：
实际执行：
第1天: 等级4 (峰值-1)
第2天: 等级4 (受天数约束，不能到5)
第3天: 等级3
第4天: 等级2
```
由于天数约束，实际峰值被限制为4而非5。

### 案例3：无痛经
```
随机到等级0：
所有天数痛经等级都是0
```

## 技术实现

### 数据存储
```python
# 存储结构
{
    "dysmenorrhea_cycle1": {
        "peak_level": 5,          # 该周期的痛经峰值
        "last_check_date": "2025-12-16"
    },
    "dysmenorrhea_cycle2": {
        "peak_level": 0,          # 第二周期无痛经
        "last_check_date": "2026-01-10"
    }
}
```

### 计算逻辑
```python
def _calculate_dysmenorrhea_level(day_in_phase, cycle_num, today):
    # 1. 获取或生成该周期的痛经峰值
    peak_level = get_or_generate_peak_level(cycle_num)
    
    if peak_level == 0:
        return 0
    
    # 2. 根据天数计算当前等级
    if day_in_phase == 1:
        current_level = peak_level - 1
    elif day_in_phase == 2:
        current_level = peak_level
    else:
        current_level = peak_level - (day_in_phase - 2)
    
    # 3. 应用天数约束
    current_level = min(current_level, day_in_phase - 1)
    
    return max(0, current_level)
```

## 用户体验提升

1. **更真实**：符合痛经的自然变化规律
2. **更合理**：不会出现逻辑矛盾（如高等级但只持续1天）
3. **更可预测**：用户可以预期痛经会逐渐缓解
4. **更简洁**：7个等级比11个等级更易理解
